# FUNNEL.md — Детальное описание воронки обработки вакансий

Этот документ описывает трёхэтапную воронку фильтрации и анализа вакансий в HH-Parser.

---

## Общая схема воронки

```
┌─────────────────────────────────────────────────────────────────────┐
│  ВХОД: hh.ru API                                                     │
│  ↓ ~100-500 вакансий из поиска                                      │
└─────────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────────┐
│  ЭТАП 1: ПАРСИНГ + ПРЕДФИЛЬТРАЦИЯ                                   │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐          │
│  │ hh.ru поиск  │───▶│ PreFilter    │───▶│ Парсинг      │          │
│  │ (превью)     │    │ по заголовку │    │ полной стр.  │          │
│  └──────────────┘    └──────────────┘    └──────────────┘          │
│                                                                      │
│  Фильтрация: по черному списку, whitelist, стеку технологий         │
│  Выход: ~20-50 вакансий (статус: parsed)                            │
└─────────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────────┐
│  ЭТАП 2: БЫСТРЫЙ СКОРИНГ (Quick Score)                              │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐          │
│  │ Batch запрос │───▶│ LLM оценка   │───▶│ Скор 1-10    │          │
│  │ всех вакансий│    │ по описанию  │    │ + краткое    │          │
│  └──────────────┘    └──────────────┘    └──────────────┘          │
│                                                                      │
│  1 запрос к LLM на все вакансии                                     │
│  Фильтрация: скор >= minScore (default: 5)                          │
│  Выход: ~10-20 вакансий (статус: ready_for_deep)                    │
└─────────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────────┐
│  ЭТАП 3: ГЛУБОКИЙ АНАЛИЗ (Deep Analysis)                            │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐          │
│  │ Детальный    │───▶│ Генерация    │───▶│ Создание     │          │
│  │ анализ + AI  │    │ письма       │    │ отчёта       │          │
│  └──────────────┘    └──────────────┘    └──────────────┘          │
│                                                                      │
│  Параллельная обработка топ-N вакансий (default: 10)                │
│  Выход: analyzed вакансии + .md отчёты                              │
└─────────────────────────────────────────────────────────────────────┘
```

## ЭТАП 1: Парсинг + Предфильтрация

### 1.1 Генерация фильтров поиска

**Модуль:** `src/filters.js`

Из резюме извлекаются параметры для API hh.ru:

```javascript
{
  text: "fullstack разработчик",        // Основной запрос
  area: 1,                               // Москва
  experience: "between1And3",            // Опыт работы
  employment: "full",                    // Полная занятость
  schedule: "remote",                    // Удалённо
  search_field: "name,description"       // Искать в названии + описании
}
```

**Кэширование:** Фильтры кэшируются в `data/filters-cache.json` и обновляются только при изменении резюме.

### 1.2 Получение превью вакансий

**Модуль:** `src/parser.js → parseSearchPage()`

С каждой страницы поиска извлекаются:
- `id` — уникальный идентификатор
- `name` — заголовок вакансии
- `salary` — зарплата (если указана)
- `companyName` — название компании
- `area` — город
- `snippet` — краткое описание (requirement + responsibility)
- `url` — ссылка на вакансию

**Пример превью:**
```json
{
  "id": "123456",
  "name": "Fullstack разработчик (React + Node.js)",
  "salary": "от 150 000 до 250 000 руб.",
  "companyName": "ООО Технологии",
  "area": "Москва",
  "snippet": {
    "requirement": "Опыт с React, TypeScript, Node.js от 2 лет",
    "responsibility": "Разработка веб-приложений"
  },
  "url": "https://hh.ru/vacancy/123456"
}
```

### 1.3 PreFilter — фильтрация по заголовку

**Модуль:** `src/preFilter.js`

**Цель:** Отсечь неподходящие вакансии **до** парсинга полной страницы (экономия времени и запросов).

**Критерии фильтрации:**

#### Blacklist (автоотклонение)
```javascript
blacklistPatterns: [
  /1c/i, /битрикс/i, /laravel/i,
  /senior/i, /lead/i, /team lead/i,
  /flutter/i, /android/i, /ios/i
]
```

#### Whitelist (автопринятие)
```javascript
whitelistPatterns: [
  /fullstack/i, /full-stack/i, /full stack/i,
  /react.*node/i, /node.*react/i
]
```

#### Скоринг по стеку технологий

**Мой стек (из резюме):**
```javascript
myStack: ["react", "node.js", "typescript", "next.js", "express"]
```

**Чужой стек (не моё):**
```javascript
otherStack: ["php", "java", "python", "1c", "laravel"]
```

**Формула PreScore:**
```javascript
preScore = (myStackMatches * 2) - (otherStackMatches * 1.5)
```

**Решение:**
- `preScore < minPreScore` (default: 0) → **отклонить**, не парсить
- `preScore >= minPreScore` → парсить полную страницу

**Пример:**
```
Вакансия: "React/Node.js разработчик"
myStackMatches: 2 (react, node.js)
otherStackMatches: 0
preScore = 2 * 2 - 0 * 1.5 = 4 ✅ Парсим

Вакансия: "Fullstack PHP/React разработчик"
myStackMatches: 1 (react)
otherStackMatches: 1 (php)
preScore = 1 * 2 - 1 * 1.5 = 0.5 ✅ Парсим

Вакансия: "Senior Java/Spring разработчик"
myStackMatches: 0
otherStackMatches: 1 (java)
preScore = 0 * 2 - 1 * 1.5 = -1.5 ❌ Отклонить
```

### 1.4 Парсинг полной страницы

**Модуль:** `src/parser.js → parseVacancyPage()`

Извлекаются полные данные:
- Описание вакансии (HTML)
- Требования
- Условия
- Ключевые навыки
- Контакты (если есть)
- Адрес офиса (если есть)

**Сохранение:** `data/vacancies/{id}.json` + запись в `data/processed.json` со статусом `parsed`.

**Задержки между запросами:** 3-10 секунд (рандом) для обхода блокировок hh.ru.

## ЭТАП 2: Быстрый скоринг (Quick Score)

### 2.1 Цель этапа

Быстро оценить все спарсенные вакансии **одним batch-запросом** к LLM, чтобы отсеять явно неподходящие.

**Зачем batch:** Экономия токенов и времени. Вместо 50 запросов делаем 1 запрос с массивом вакансий.

### 2.2 Подготовка данных

**Модуль:** `src/analyzer.js → quickScore()`

Для каждой вакансии берём урезанное описание:
```javascript
{
  id: "123456",
  name: "Fullstack разработчик",
  description: "Первые 500 символов описания..." // Экономим токены
}
```

### 2.3 Промпт для LLM

```
Ты — AI-ассистент для оценки вакансий.

РЕЗЮМЕ КАНДИДАТА:
[полный текст резюме]

ВАКАНСИИ (массив):
[
  {
    id: "123456",
    name: "Fullstack разработчик",
    description: "..."
  },
  ...
]

ЗАДАЧА:
Оцени каждую вакансию по шкале 1-10:
- 1-3: Совсем не подходит
- 4-6: Частично подходит
- 7-8: Хорошо подходит
- 9-10: Идеально подходит

ФОРМАТ ОТВЕТА (строго JSON):
[
  {
    "id": "123456",
    "score": 8,
    "reason": "Стек совпадает, требования адекватны"
  },
  ...
]
```

### 2.4 Обработка результата

**Фильтрация:**
```javascript
if (score >= config.funnel.quickScore.minScore) {
  status = "ready_for_deep"  // Идёт на глубокий анализ
} else {
  status = "quick_scored"    // Отклонена
}
```

**Статистика:**
```
Этап 2: Быстрый скоринг завершён
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Обработано: 45 вакансий
  Прошли фильтр (≥5): 18 вакансий
  Отклонено: 27 вакансий
  Средний скор: 5.2
```

## ЭТАП 3: Глубокий анализ (Deep Analysis)

### 3.1 Отбор топ-N вакансий

**Модуль:** `src/index.js` (режим `funnel`)

Берём топ-N вакансий по скору (default: 10).

**Сортировка:**
```javascript
vacancies
  .filter(v => v.status === "ready_for_deep")
  .sort((a, b) => (b.quickScore || 0) - (a.quickScore || 0))
  .slice(0, topN)
```

### 3.2 Параллельная обработка

**Параметр:** `--parallel` (default: 3)

Обрабатываем несколько вакансий одновременно, чтобы ускорить процесс:

```javascript
// Разбиваем на батчи по 3 вакансии
for (let i = 0; i < vacancies.length; i += parallel) {
  const batch = vacancies.slice(i, i + parallel);
  await Promise.all(batch.map(v => deepAnalyze(v)));
}
```

### 3.3 Глубокий анализ вакансии

**Модуль:** `src/analyzer.js → deepAnalyze()`

Для каждой вакансии:

#### 3.3.1 Детальный анализ

**Промпт:**
```
РЕЗЮМЕ:
[полное резюме]

ВАКАНСИЯ:
[полное описание вакансии]

ЗАДАЧА:
Проанализируй вакансию и верни JSON:
{
  "matchPercentage": 85,
  "pros": ["React есть", "Зарплата подходит"],
  "cons": ["Нужен опыт с GraphQL"],
  "missingSkills": ["GraphQL", "Docker"],
  "salaryMatch": "подходит",
  "detailedAnalysis": "Подробный анализ..."
}
```

**Результат сохраняется в:** `vacancy.analysis`

#### 3.3.2 Генерация Key Facts

**Промпт:**
```
На основе анализа вакансии создай 5-7 ключевых фактов для сопроводительного письма:
- Что именно подходит в опыте кандидата
- Какие проекты релевантны
- Почему кандидат заинтересован

ФОРМАТ:
["Факт 1", "Факт 2", ...]
```

**Результат сохраняется в:** `vacancy.keyFacts`

#### 3.3.3 Генерация сопроводительного письма

**Модуль:** `src/analyzer.js → generateHumanCoverLetter()`

**Промпт:**
```
РЕЗЮМЕ:
[резюме]

ВАКАНСИЯ:
[вакансия]

KEY FACTS:
[keyFacts]

ЗАДАЧА:
Напиши сопроводительное письмо на русском языке:
- Естественный, живой стиль
- Без клише ("с интересом рассмотрел")
- Конкретные примеры из опыта
- 150-250 слов
```

**Результат сохраняется в:** `vacancy.coverLetter`

#### 3.3.4 Генерация вопросов работодателю

**Промпт:**
```
Сгенерируй 3-5 умных вопросов работодателю на собеседование:
- О процессах разработки
- О команде
- О технологиях
- О возможностях роста

ФОРМАТ:
["Вопрос 1?", "Вопрос 2?", ...]
```

**Результат сохраняется в:** `vacancy.questions`

### 3.4 Сохранение результатов

**Обновление статуса:** `analyzed`

**Создание отчёта:** `output/{id}.md`

**Структура отчёта:**

## Метрики воронки

### Пример прохождения

```
ВХОД: 100 вакансий с hh.ru

ЭТАП 1: Парсинг + PreFilter
├─ Отклонено PreFilter: 35 (blacklist, низкий preScore)
├─ Ошибки парсинга: 5
└─ Спарсено: 60 вакансий (статус: parsed)

ЭТАП 2: Быстрый скоринг
├─ Низкий скор (<5): 40
└─ Прошли фильтр: 20 вакансий (статус: ready_for_deep)

ЭТАП 3: Глубокий анализ (топ-10)
├─ Успешно: 9
├─ Ошибки: 1
└─ Проанализировано: 9 вакансий (статус: analyzed)

ВЫХОД: 9 вакансий + отчёты
```

### Конверсия

```
100 вакансий → 9 финальных (9% конверсия)
```

**Это нормально:** цель воронки — отфильтровать шум и оставить только реально подходящие вакансии.

## Управление лимитами Groq API

### Отслеживание лимитов

**Модуль:** `src/groq-client.js`

Для каждой модели отслеживаются:
- Токены за минуту (TPM)
- Запросы за минуту (RPM)

### Автопауза

При достижении **80% лимита** (по токенам ИЛИ запросам):
```
⏸️  Пауза на 60 секунд (достигнут лимит)
```

### Retry при 429

При ошибке "rate limit exceeded":
- Пауза 60 секунд
- Повтор запроса
- Максимум 3 попытки

## Настройка воронки

### Параметры в config.js

```javascript
preFilter: {
  enabled: true,          // Включить/выключить предфильтрацию
  minPreScore: 0          // Минимальный preScore для парсинга
},
funnel: {
  quickScore: {
    minScore: 5,          // Минимальный скор для глубокого анализа
    descriptionLength: 500 // Длина описания для скоринга (токены)
  },
  deepAnalysis: {
    topN: 10,             // Количество вакансий для глубокого анализа
    parallelRequests: 3   // Параллельных запросов к LLM
  }
}
```

### CLI флаги

```bash
# Изменить минимальный скор
npm run funnel -- --min-score 7

# Изменить количество топовых вакансий
npm run funnel -- --top-n 15

# Изменить параллелизм
npm run funnel -- --parallel 5
```

## Оптимизация производительности

### Экономия токенов

1. **PreFilter:** отсекаем 30-40% вакансий до парсинга
2. **Урезанное описание:** в quickScore используем только 500 символов
3. **Batch запрос:** 1 запрос вместо 50 для скоринга
4. **Топ-N:** глубоко анализируем только лучшие

### Экономия времени

1. **Параллельная обработка:** 3 вакансии одновременно на этапе 3
2. **Кэширование:** резюме и фильтры не пересоздаются каждый раз
3. **Минимум задержек:** задержки только между запросами к hh.ru

### Типичное время выполнения

```
ЭТАП 1 (парсинг 50 вакансий):  ~3-5 минут
ЭТАП 2 (скоринг 50 вакансий):  ~10-20 секунд
ЭТАП 3 (анализ 10 вакансий):   ~2-3 минуты

ИТОГО полный цикл:             ~6-9 минут
```

## Обработка ошибок

### Сетевые ошибки (hh.ru)

- Retry 3 раза с задержкой
- Если все попытки провалились → пропуск вакансии
- Детекция капчи → остановка парсинга

### Ошибки LLM

- Retry при 429 (rate limit)
- Невалидный JSON → повторный запрос с уточнением
- Timeout → переход к следующей вакансии
- Статус вакансии → `error`

### Graceful Shutdown

При `Ctrl+C`:
1. Сохранение текущего состояния
2. Обновление статусов в processed.json
3. Вывод статистики
